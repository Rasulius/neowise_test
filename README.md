### 🚀 Инструкция по запуску и тестам
- Запуск сервера: `node server.mjs`
- Прогон тестов: `node --test triage.test.mjs`

### 🔍 Где проверяется результат AI
Результат ответа имитатора AI проверяется на сервере в файле `server.mjs`, в обработчике `handleTriage` маршрута `POST /api/triage`. После вызова `classify(...)` из `mock-ai.mjs` ответ парсится как JSON и валидируется: `topic` должен быть одним из `delivery`, `pricing`, `other`, а `draft` — непустой строкой (после `trim`). При успешной проверке API возвращает `{"status":"ready","topic":"…","draft":"…"}`. На клиенте (`index.html`) при `status: "ready"` отображаются тема и черновик.

### ⚠️ Что происходит при сбое
Ожидание ответа модели ограничено 300 мс (`AbortSignal.timeout(300)`). При таймауте, ошибке модели, невалидном/неподходящем ответе (битый JSON, недопустимая тема, пустой черновик) сервер возвращает HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. На странице в этом случае показывается сообщение «Требуется ручной разбор» и очищается предыдущий черновик; при сетевой ошибке запроса на клиенте также показывается ручной разбор. При некорректном вводе (пустой/отсутствующий/нестроковый `text`, битый JSON запроса) возвращается HTTP 400 и `{"status":"invalid_input"}`.

### 🤖 Использованный AI и ручная проверка
- **AI:** Iceman OpenCode
- **Проверено самостоятельно:** Проверена валидация входных данных, разбор и проверка ответа модели (допустимые темы, непустой черновик), обработка таймаута/ошибок/неподходящих ответов с возвратом `manual_review`, а также отображение результата и очистка предыдущего черновика в интерфейсе; добавлены и прогнаны автоматические тесты (`node --test triage.test.mjs`).

### 💼 Польза для менеджера и метрика
Автоматический триаж сокращает время первичной обработки входящих заявок с минут до секунд, позволяя измерять эффективность через метрику "среднее время реакции на тикет" (First Response Time) и снижая нагрузку на первую линию поддержки.
